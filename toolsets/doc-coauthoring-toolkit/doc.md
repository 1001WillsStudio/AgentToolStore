# Document Co-Authoring

Collaboratively write structured, polished documents with the user.

## Overview

This skill enables a structured co-authoring workflow where you and the user build a document together. It's ideal for documents that benefit from structure: proposals, design docs, decision memos, specifications, and similar content.

## The Co-Authoring Process

### 1. Understand the Document

Before writing, clarify:
- **Purpose**: What decision/action should this document drive?
- **Audience**: Who will read this? What do they care about?
- **Format**: Is there a required template or structure?
- **Scope**: What's in scope and out of scope?
- **Tone**: Formal, informal, technical, executive?

### 2. Outline First

Always start with an outline. Don't write prose until the structure is agreed on:

```
# [Document Title]

## Executive Summary
- [One-paragraph summary of the key point]

## Background
- [Context the reader needs]

## [Main Section 1]
- [Key points]

## [Main Section 2]
- [Key points]

## Recommendations / Next Steps
- [Action items]
```

Get the user's approval on the outline before writing.

### 3. Draft Section by Section

- Write one section at a time
- After each section, ask for feedback before continuing
- This keeps the user engaged and prevents wasted work from wrong direction

### 4. Iterate

- Incorporate feedback on each section
- Revise earlier sections as later ones clarify the argument
- Maintain consistency in tone and terminology

### 5. Polish

- Check for logical flow between sections
- Ensure consistent formatting
- Verify all claims are supported
- Add supporting materials (diagrams, tables, references)

## Document Types and Structures

### Design Document
```
# [Feature/System Name] Design Document
## Summary
## Problem Statement
## Goals and Non-Goals
## Proposed Design
## Alternatives Considered
## Trade-offs and Risks
## Implementation Plan
## Open Questions
```

### Decision Memo
```
# Decision: [Topic]
## Recommendation
## Context
## Options Considered
## Analysis
## Risks and Mitigations
## Next Steps
```

### Project Proposal
```
# Proposal: [Project Name]
## Executive Summary
## Problem and Opportunity
## Proposed Solution
## Timeline and Milestones
## Resources Required
## Success Metrics
## Risks and Dependencies
```

## Guidelines

- **Outline first, always**: Never write prose without agreed structure
- **One section at a time**: Don't draft the whole document at once
- **Ask for feedback frequently**: After each section, not after the full draft
- **The user is the expert on content**: You provide structure and writing; they provide domain knowledge
- **Be responsive to tone**: Match the user's preferred level of formality
- **Flag assumptions**: Explicitly note where you're filling gaps vs. representing stated facts
